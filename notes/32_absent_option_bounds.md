# 32 —— 后继值缺失的 mex 上界共享，以及跨宽度调度的短筛选

日期：2026-10-16。状态：`[标准 mex 恒等式的算法应用]`、`[有界实验]`、
`[独立小图核验]`。本轮没有新增完整空盘值，目标仍是精确连续求到 100。

## 1. 先排除一种缓存遗漏

原定向查询对已经完成的 `(规范连通局面,目标)` 有缓存：找到同值后继就
记录目标排除，确定了准确 mex 就记录准确值。检查代码没有发现同一已完成
查询被反复递归证明的遗漏。不同目标仍可能需要许多不同后继。

另检验跨宽度共享同一张表，避免只用每个空盘的新进程来判断可扩展性。
令 F_n 是完整三行盘，A_n 只删右端中格，D_n 删两端中格。三种调度均从
宽1开始，以同一个原定向求解进程顺次求值；参考答案只在运行后比对，
没有注入 C 求解器。

| 同宽作业顺序 | 2 秒内完整完成的作业 | 第一个未完成作业 |
|---|---|---|
|F|F_1..F_27，共27项|F_28|
|A,D,F|宽1..21，共63项|A_22|
|D,A,F|宽1..21，加D_22，共64项|A_22|

F 调度完成27时的累计状态数为109,130、递归着法983,761、缓存探查
2,073,687。它没有越过28。预先求辅助序列也没有显示收益：A_22 的已知
SG=11，但证明其准确值仍昂贵。不能把“先把 A/D 表算好”当成免费的加速。
表中的作业数是**超时前已完整输出且与参考一致的前缀**，不是连续到34。

`STRIP3_TARGET_BATCH_PROGRESS=1` 新增逐作业的累计计数及及时刷新输出。
默认关闭，原默认算法的18/24确定性操作数回归保持不变。

## 2. 新的共享单位：不求准确 mex，先证明上界

设 O(G) 是全部合法后继的 SG 值集合。引入独立查询

```
A(G,j) := j 不属于 O(G)。
```

由 mex 定义，**A(G,j) 蕴含 g(G)≤j**；它不蕴含 g(G)=j。一个这样的证据
可以直接否定所有 `g(G)=k, k>j`，不必先补齐所有较小值的证明。
这是一条标准 mex 性质，不声称是新的游戏结构定理。

对每个连通局面保存：

- W：已经有实际合法后继作为见证的 SG 值集合；
- U：已经证明缺失的最小后继值，初始为顶点数 |V|；
- 已经确定的准确值（若有）。

初始 U 有效，因为每手至少删一点，后继 SG≤|V|−1。由这些证据总有

```
L = mex(W) ≤ g(G) ≤ U。
```

L=U 时可发布准确值。实现区分“实际选项值”和“一般的目标否定”：仅凭
g(G)≤U 不能把 k>U 当作实际选项值写入 W。

证明 A(G,j) 时完整检查每个合法后继是否等于 j；遇到一个等值后继，给 W
加入 j，A 为假；全部否定则降低 U。已有 U 本身携带 A(G,U) 证据，但不能
据此断言所有大于 U 的后继值也缺失。

等值查询 E(G,k) 先读区间和 W，再检查 A(G,k)，并补齐所需的低值选项
见证。若其间证明 A(G,j) 且 j<k，直接否定高目标，不继续求准确 mex。
另提供两个有限探查策略：高目标 k 先尝试 j=k−1 或 floor(k/2)。
探查失败只产生一个真实选项见证，不影响正确性。

每次递归等值查询都来自一个真实后继或其连通分量，顶点数严格下降。
检查本局面较小 j 时调用 A，再去查询更小图；不需要递归证明本局面的
准确低 mex。按顶点数归纳可证明上述所有区间和准确值正确。

原型为 `src/cfast/strip3_absence.c`。每槽另加一个字节保存上界，默认筛选
2^22 槽即4 MiB；几何、缓存键、分组件和与原型一致。仍只有42列能力，
没有把它写成100列程序。

## 3. 短筛选：确有上界复用，净工作量没有改善

代码冻结于 `47bd0a0`，最终数据记录实际源码SHA256。三种配置分别是：

1. j=k−1 探查，不做缓存选项预扫描；
2. 不额外探查，做缓存选项预扫描；
3. j=floor(k/2) 探查，做缓存选项预扫描。

每种均按尺寸递增，28首次2秒未完成即停；没有增加确认时长。三种配置都
只完成了28的目标0..3，未给出根SG。

第三种是本轮较好的配置，但与 notes/30 已有较好配置比较仍更贵：

| n | 原配置状态 | 上界配置状态 | 原递归着法 | 上界配置递归着法 | 原缓存探查 | 上界配置缓存探查 |
|---:|---:|---:|---:|---:|---:|---:|
|24|5,544|6,170|50,220|102,428|93,987|103,657|
|26|11,848|12,763|129,229|294,515|240,360|267,226|

两类操作合计分别从144,207增到206,085，从369,589增到561,741。
它们不是总CPU指令数，但均没有显示工作量节省。上界缓存确实直接否定了
24的590次、26的1,511次后来查询；不能因为出现剪枝次数就宣布加速。
获取这些上界及候选探查的开销超过了本次节省。

三个上界筛选批次分别约3.21、3.15、3.08秒，原程序三种共享调度一批
约6.65秒；包含各自编译，四批合计约16.28秒。每个求解进程均为单核、
单线程、512 MiB、最多2秒。总预算在各批/进程间检查余量；生成和保存
小型JSON的Python步骤没有单独硬中断。单次计时不作为稳定速度比证据。

新原型仅作为已筛选实验保存，不替换默认定向搜索或生产数据管道。

## 4. 独立核验与复现

直接子集 mex 不使用组件分解、几何规范化、区间或目标递推。七种探查/
着法/缓存配置均与全部32,768个3×5诱导图的准确SG一致，并通过合计
2,523,136次乱序等值查询；包括最终筛选的全部三个配置。66个跨64/126位的
稀疏图由独立坐标图mex核验。
非法探查配置、内存和工作量用尽不产生未完成SG。

原引擎另外通过全部3×5诱导图、2,293,760次乱序查询及原18/24操作数回归。
新批次进度开关没有改变默认搜索。

调度器用受限伪进程验证：杀掉正在运行的后续作业后只保留已刷出的完整
首项；错误值、非法输出、干净退出但输出不全均拒绝。真实求解器的12个
短作业逐项进度与SG输出匹配。完整数据为：

```
data/strip3_absence_previous_screen.json
data/strip3_absence_no_probe_screen.json
data/strip3_absence_half_screen.json
data/strip3_shared_sequence_screen.json
```

## 5. 下一步需要区分的两个问题

本轮没有证据支持继续扩大上界缓存或预先求更长辅助序列。缓存已完成命题
与使用不准确的区间都不足以消去厚块中大量不同的证明义务。

更有价值的诊断是：**在当前证明规则内，存在的短证书本身是否已经很大，
还是搜索为寻找证书展开了太多无用分支？** 可先在秒级可求的较小盘上用
准确值引导的离线证书优化作对照，并明确区分树证书、共享DAG和求证开销。
这样的离线oracle不能冒充求解未知100的算法。只有发现可扩展的证书规律，
或直接消去完整厚块的方法，才有理由进入更大盘确认。
