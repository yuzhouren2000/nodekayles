# 26 —— 已证梳臂规则对完整空盘搜索的实际贡献

日期：2026-10-14。状态：`[实测]`。全部在本机执行，没有使用服务器。

本节回答“最近的结构结论对搜索究竟有多大帮助”。区分两个问题：符合定理
的单个局面能否直接算，以及完整空 `3×n` 的搜索是否因此少做很多工作。
前者已有明确答案；后者必须把规则接入相同求解器后比较。

## 1. 此次接入的精确范围

`src/cfast/strip3.c` 增加两个可关闭的归约位，原默认值仍为 7：

| 位 | 覆盖的整个连通分量 | 依据 |
|---|---|---|
| 8 | `reverse(a(n)),6,7^w,6,a(m)`，w=2,3,4,5 | notes/23 双臂完整证书 |
| 16 | `reverse(a(n)),6776,a(ℓ),67776,a(m)`，ℓ 正奇数 | notes/24–25 三长度完整证书 |

这里 `a(t)=(4,6,4,6,… 长度t)`；包括短臂、零外臂、短桥和所有反射。
识别器要求**整个连通分量**恰好符合列词，不把残缺厚块或任意内部子词当作
完整核心。总宽最多 42，与当前 C 掩码上限一致。

有限 C 查表由已证明的无限查询器导出，不运行新的图枚举。导出时重新独立
核验四张单厚块证书与整个三长度捆绑证书，并检查图、根及相位。头文件记录
输入证书 SHA256；`--check` 检查导出是否过期。

这只测上述完整核心识别器的贡献。证书包含的全部动态残缺核心、一般一根
稳定定理和其他结构规则没有在本次统一接入。因此结果不是所有可能实现的
收益上界。

## 2. 比较方式与核验

配置 7 为原有路径/环、安全旋转、相同分量抵消；15 仅加单厚块，23 仅加
双厚块，31 两者都加。每个输入均从新进程、新记忆表开始，保持同一二进制、
单线程、相同预分配 `2^24` 槽预算。固定一个本机 CPU，每组重复三次，轮换
配置顺序。记录 SG、记忆状态、调用、着法、命中次数及进程实际时间。

完整空盘采用 `board N`，分别测 N=18,20,22,24。它不同于 `strip N` 的共享
前缀表，不能直接拿旧 `strip 20` 的计数来比较。原始样本、编译参数和源码、
表、二进制的 SHA256 均保存在 `data/strip3_comb_benchmark.json`。

正确性检查包括：

- 全部 6,307 个 42 列以内参数记录，SG 与关闭新规则的 C 递归完全一致。
- 26,382 个反射、平移、单格修改的形状检查，防止误识别残缺核心。
- 32 种归约配置下，`3×5` 的全部 32,768 个诱导局面与独立子集 mex 一致。
- 327 个跨 64/126 位的稀疏图及双线程输出一致；原多字 C 核对 689 个完整/
  端缺口/首着局面。

## 3. 测量结果

下面比较原配置 7 与两类新规则均启用的配置 31；时间为三次进程实际时间的
中位数。各配置的 SG 和重复运行的状态/着法计数均一致。

| 空盘 | 记忆状态，关闭/开启 | 单厚块/双厚块命中 | 枚举着法减少 | 耗时，关闭→开启（秒） |
|---|---:|---:|---:|---:|
| `3×18` | 109,656 / 109,656 | 198 / 77 | 0.2164% | 0.449 → 0.450 |
| `3×20` | 370,021 / 370,021 | 259 / 139 | 0.0906% | 1.590 → 1.560 |
| `3×22` | 1,250,062 / 1,250,062 | 328 / 226 | 0.0366% | 6.024 → 6.149 |
| `3×24` | 4,225,816 / 4,225,816 | 405 / 342 | 0.0143% | 24.639 → 24.769 |

`3×24` 共 747 次命中，省去 747 次连通分量 mex 展开；着法从 178,731,814
减到 178,706,248，仅省 25,566 次。总记忆状态没有减少。单厚块、双厚块
分别启用时也都没有减少记忆状态，分别减少 0.0069%、0.0074% 的着法。

在这组范围内，耗时有正有负、幅度很小；`3×24` 关闭的三次实际时间范围
为 24.566–24.902 秒，开启为 24.382–25.682 秒，没有显著提速证据。
默认保持原配置 7。不能由这一有限实验证明所有大盘也无收益，但可以明确
说：**当前完整核心规则在已测完整空盘上总体帮助很小，没有缩小状态表。**

独立族局面则有完全不同的表现：

| 宽 42 的已解族局面 | 精确 SG | 递归调用，关闭→开启 | 枚举着法，关闭→开启 |
|---|---:|---:|---:|
| 单厚块 w=3，两臂 18、19 | 2 | 77,284 → 1 | 40,149 → 0 |
| 双厚块 2、3，外臂 11、11，桥 11 | 0 | 349,914 → 1 | 174,295 → 0 |

两个例子都有正外臂，按 notes/23、25 的上行落子历史可从空盘到达。
双厚块例子落在显式 SG 公式范围，`r(11) xor r(11) xor(12 mod4)=0`。
这准确展示了“直接算出一个子问题”的作用，不能用它代替完整空盘加速率。
把长度扩大到 `10^18` 时，Python 证书查询仍不展开长段；C 本身仍受 42 列
上限约束。

## 4. 为什么必须区别局部公式和总体提速

命中规则后，C 直接返回整个连通分量的精确 SG，省去其 mex 展开。这是准确
的子问题求解；不是仅排除某几手，也不是把非零选项从 mex 中删去。

但记忆化搜索有大量共享后继。跳过一个局面的展开，并不保证其后继不再
从别的分支访问。因此“命中 X 次”“省去 X 次 mex”“减少 X 个记忆状态”是
三个不同的计数，不能把命中次数当作省掉同样数量的整棵搜索树。

显式三长度 SG 公式要求外臂各至少 5、中桥至少 11，其最小总宽为 30。
本次空盘样本宽度至多 24，因而该**长段公式**在这些空盘搜索中不可能命中；
双厚块命中来自完整证书中的短段值。这个实验不足以判断长段公式在
`3×30` 以上完整搜索的命中率。另测宽 42 的真实可达族局面，用于确认
长段公式的直接求解能力，不能把该族的收益替代完整空盘收益。

对固定厚块的这些完整核心，参数记录数至多按 N 的多项式增长：单厚块、
总宽≤N 的记录数为（N≥7）

\[
\sum_{w=2}^{5}\frac{(N-w-1)(N-w)}2=O(N^2),
\]

双厚块为

\[
\sum_{\substack{1\le\ell\le N-9\\\ell\text{ 奇数}}}
\frac{(N-8-\ell)(N-7-\ell)}2=O(N^3).
\]

这是参数记录的上界，包含零外臂，尚未除去对称或排除抽象不可达记录。
notes/17 则表明真实连通几何有更多形状。但**几何计数不是搜索复杂度下界**：
一个常见的归约仍可能省掉很大子树，能否提速要以实测为准。

关键数学边界仍是：现有结论压缩的是固定厚块周围的长臂和长桥；完整空盘
随 n 增长时，厚块本身也不断变宽，并出现更多残缺核心及多个厚块。没有
统一处理这一方向，就不能声称破解了完整 `3×n` 的搜索规律。

## 5. 复现

```bash
make export-strip3-comb       # 重新独立核验证书并导出 C 表
make test-strip3-comb
make test-strip3
make benchmark-strip3-comb   # 本机串行，共四组空盘和两个族局面
STRIP3_REDUCTIONS=31 ./src/cfast/strip3 board 20
```

计时主要参考空盘的三次中位数；两个族局面耗时太短，以调用和着法数为主要
证据。当前 CLI 的 `memo` 只报告 120 位紧凑表条目，41–42 列稀疏图另有宽键
表，因此族样本不报告总记忆状态节省比例。N≤24 的空盘计数没有这一缺口。
