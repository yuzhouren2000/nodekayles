# 29 —— 用 3×100 牵引方法，以及秒级实验的第一轮结果

日期：2026-10-16。目标尚未完成。

## 1. 目标与验收

主目标改为：**连续精确求出完整空盘 `G(3×n)`，`1≤n≤100`**，并提供可复现的
程序或可独立检查的证明/证书。仅判断胜负、拟合周期或解出特殊缺口族，都不
代表完成。现有连续精确数据到 34。

首个验收门槛是快速复现已有前缀，初步争取在本机单核、秒到十秒级完成到 34；
随后看 40、60、100 的实际资源增长。这个门槛是研究筛选标准，不是“任何能解
100 的算法都必须快速解出所有较小尺寸”的数学命题，特殊尺寸的直接证明也有价值。

## 2. 为什么必须更换展开方式

notes/17 的完整连通几何计数递推给出：

```
跨度≤34：            16,943,956,496 个状态
跨度≤100：4,964,529,529,960,291,031,205,969,562 个状态
比值：约 2.93×10^17
```

后一项是假设枚举整个语言时的状态容量，**不是所有算法的时间/空间下界**。
即使每状态只占一字节，也已不可用；靠多线程、更多 RAM 或常数倍加速无法
沿这条路线达到目标。notes/27 的搜索下界也只约束所声明的完整 SG 展开框架，
不排除定向真假查询、证明共享或新的上下文归约。

notes/28 原稿把宽度 4–8 的实验写成“可达族不存在有限接口”，此次已纠正：
现有证据只给出这些宽度的完整行为类数，以及至少 951 个状态的门槛。
不能将有限实验外推成无限不可能性定理。

## 3. 实验纪律

1. **正确性先行**：用独立的子集 mex、小图及位边界样本排错，通常数秒。
2. **默认筛选**：每进程 2 秒、总计 20 秒（含编译）、单核、地址空间 512 MiB。
   每尺寸新进程；记录源码哈希、Git 基点、配置、状态/查询/着法数和完整输出。
   候选首次失败即停止该批；参考程序首次超时后不再重复浪费其超时预算。
3. **确认须有理由**：状态数显著减少或证明带来可检查的新预测，才安排单独
   确认，先控制在一分钟内。超时不是计算结果，不输出伪造的 SG。
4. **规模不单调**：一个较小尺寸失败不代表所有更大尺寸都失败；如有不同
   查询目标或已知结构，可另开有明确理由的小实验，不能混成连续前缀已完成。
5. **不把重复长算当进展**：已有结果优先读证书；未改动的昂贵测试不反复重算。
   背景负载下优先比较确定性的操作计数，稳定时间加速比另需受控重复测量。

入口：`make test-strip3-target-search`、`make screen-strip3`。
筛选脚本也接受采用 `board N` 输出 `3 N SG` 的其他 C 候选源码；不把研究绑在
当前原型上。默认失败停止，不会自动转为小时级任务。

### 增量缓存与冷启动测量

`screen_strip3.py` 现在默认从 `--output` 复用已核验完成的样本；也可用
`--cache PATH` 指定独立的缓存文件。追加尺寸只计算新增尺寸，缩小请求不会丢失
其他已完成尺寸。每次落盘采用原子替换，中断后可继续读取此前已保存的完整结果。
`--fresh` 忽略旧缓存并重新编译、测量，用于需要重新取样的冷启动实验。

缓存只收录返回码为 0、输出恰为 `3 n SG` 且与已知精确值一致的完成行；超时、
失败和错误值不作为结果复用。兼容指纹覆盖递归的本地 include 源码、筛选脚本、
编译器和参数、CPU 特征、相关构建环境、算法配置、单次时间和内存限制。
这些内容变化即拒绝旧缓存；只改文档产生的新 Git 提交不会触发重算。
每条记录保留实际测量时的提交、限制和耗时，缓存命中标为 `cached: true`；
该行的 `wall_s` 是原求解耗时，报告顶层 `wall_s` 才是本次调度耗时。

真实 CLI 回归检查以下确定性工作计数（单独的 `--cache` 和 `--output`）：

| 请求 | 编译次数 | 求解器进程 | 缓存命中 |
|---|---:|---:|---:|
| 首次 12、16 | 1 | 2 | 0 |
| 再次 12、16 | 0 | 0 | 2 |
| 追加为 12、16、18 | 1 | 1 | 2 |
| 缩小为 12 | 0 | 0 | 1 |
| 恢复为 12、16、18 | 0 | 0 | 3 |

`make test-strip3-screen-cache` 还核对非法缓存行、失效指纹、强制重测和配置变化，
本轮整套回归约 1.6 秒。缓存避免重复工作，**没有降低新方法首次求解的复杂度**；
快速复现到 34 的验收仍须依据实际求解工作量，不能用缓存命中冒充通过，更不能
据此声称已经跨过 28 或支持 `3×100`。

## 4. 第一条新路线：保存目标查询，而非强制求出每个后继的完整 SG

设 `E(X,k)` 表示 `g(X)=k`。mex 的定义严格等价于

```
E(X,k) = (每个合法后继 Y 都不满足 E(Y,k))
         且 (每个 j<k 都不满足 E(X,j))。
```

它也等价于询问 `X+*k` 是否为 P。一个后继满足 `E(Y,k)`，就能立刻否定
`E(X,k)`，无需知道其余后继 SG。搜索保存每个连通图已排除的目标集合，以及
已有的精确值；目标未定也可以返回一次已证明的否定。

若 `X=C1+…+Ct`，先精确求值较小组件，只对最大组件保留真假查询：

```
E(X,k) = E(C1, k xor g(C2) xor … xor g(Ct))。
```

组件的异或使用标准 SG 定理，不把有共享顶点的两块错误地独立化。
递归按 `(顶点数,目标)` 的字典序严格下降：落子减顶点数，同局面查询只进入
较小目标，所以定义良好。外层依次查询 k=0,1,…，首个真值仍是**精确 SG**。
这是一项标准游戏恒等式的算法应用，不声称发现了新的空盘分类定理。

实现 `src/cfast/strip3_target.c` 复用原程序的位几何和规范化，但重写递归与缓存；
保留路径、环、安全旋转、同分量抵消及着法轨道。默认先查中行，从中心向两端
展开。原程序 `strip3.c` 和生产数据生成入口未替换。

原型仍限于 42 列；没有靠改掉位宽常量假装支持 100。每个哈希槽 48 字节，
大于原槽的 16 字节；当前筛选预留 `2^22` 槽，两程序都受同一地址空间上限控制。
这轮没有测得峰值 RSS，也没有证明最坏复杂度下降。

## 5. 快速筛选的结果与失败点

下面是默认“中行/中心优先”的单次本机结果。原状态/着法数读自已有
`data/strip3_comb_benchmark.json` 中关闭新梳尾规则的配置 7，避免再跑数十秒
旧程序；18 的计数另在本次筛选重现一致。两种程序的一个状态都指一个规范
连通图，但新程序多数状态只存部分目标的否定，未求完整 SG。

| n | SG | 原状态数 | 新状态数 | 新着法数 | 新单次墙钟秒 |
|---:|---:|---:|---:|---:|---:|
| 18 | 2 | 109,656 | 2,152 | 31,784 | 0.018 |
| 20 | 1 | 370,021 | 8,700 | 163,719 | 0.079 |
| 22 | 0 | 1,250,062 | 3,526 | 101,399 | 0.043 |
| 24 | 1 | 4,225,816 | 8,586 | 277,486 | 0.094 |
| 26 | 0 | 本轮未重测 | 15,171 | 661,233 | 0.195 |

24 的图状态数减少约 **492 倍**，着法数由 178,731,814 减少约 **644 倍**。
不能将状态节省倍数直接称为时间或实际内存加速比。此前的 `survey 34` 后台
任务仍在运行，时间只用作量级参考；本轮未停止该已有任务。

**明确失败点：28。** 默认 2 秒未完成；因上述大幅计数下降而安排的一次
8 秒确认仍未完成，随后停止。优先试探同局面目标 0 的变体也未越过 28，
且 24 的状态数升至 64,990，故未作为默认策略。这说明高目标的真假证明仍会
膨胀；尚未快速复现全部已有前缀，也不能估计 100 的耗时。

随后给顶层每个已完成的目标查询加上日志，一次 2 秒定位显示：28 的目标
0、1、2、3 均已排除，累计约 0.86 秒、64,253 个状态；超时时正在处理目标
**4**，所以不能只笼统地说“28 太大”。另以独立 2 秒限额检查已知 P 盘 30，
也未完成；28 的失败不能说明所有更大尺寸都会同样失败，反过来也不能跳过
28 宣称连续前缀完成。这两次诊断均没有产生新 SG 值。

独立正确性核验：

- 不使用分组件、对称或目标递推的子集 mex，穷尽全部 **32,768 个 3×5 诱导图**；
- 四种着法/目标顺序下 **1,310,720 次乱序目标查询**，以及每个图的精确 SG；
- **66 个跨 64/126 位的稀疏图**，独立坐标图 mex 一致；
- 非法输入拒绝；内存表用尽以非零退出，且不输出未完成的 SG。

可复查的数据：

- `data/strip3_target_screen_centre.json`：正式短筛选，12–26 的指定尺寸；
- `data/strip3_target_screen_low_first.json`：目标 0 优先的消融及 28 超时；
- `data/strip3_target_screen_confirmation.json`：28 的单独 8 秒确认。
- `data/strip3_target_screen_obligations.json`：28 的目标 4 瓶颈定位；
- `data/strip3_target_screen_30.json`：30 的独立 2 秒失败。

筛选源码基点为提交 `ef40236`，随后仅给 `board` 模式加了逐目标诊断输出；
各文件保留实际源码 SHA256，不能把不同版本的单次时间当作严格的消融计时。

## 6. 下一步的核心问题

**选项谱的结构筛选见[notes/40](40_option_spectrum_structure.md)**：用与 C
求解器无关的独立出口检验“选项谱坍缩成通用序列”的猜想，结论是否定的——
中行是已知分裂定理（可分离），边行被显式 2×2 检验证伪（不可分离），中行集
也不足以定 `G(F_n)`。不产生 C 需要的结构种子。

**更宽接口语义归约的后续筛选见[notes/39](39_response_equivalence.md)**：两手
回应能证明语法不同的接口等价，但10列节点减半后，11列仍触及关系工作量
上限；正式批次约2.85秒即停。没有足够规模收益，不更换默认求解器。

**结构分类的后续筛选见[notes/38](38_caterpillar_components.md)**：三行可达树
全为毛毛虫，可直接用区间DP求准确SG；但26列仅省12个状态，28仍失败。
该批含编译2.53秒便停止，没有延长失败任务。薄组件直接求值仍未消去厚块瓶颈。

**本轮后续实验见 [notes/30](30_search_obligations.md)**：联合查询、证明数搜索、
符号批量表示均未通过规模筛选；新的工作量诊断重放了一个具体障碍
`E(A(24),5)`。共享选项见证可减少小盘工作，但28仍未完成。

先研究 **28 的目标 4 中哪类连通核心占据证明开销**，以及能否用查询目标
约束、共享证明或内部厚块恒等式消去这些分支。应保存并比较证明依赖，而不
只统计空盘的最终一个数。新的结构必须对其涉及的全部后继成立，或者形成
可独立核验的定向策略证书。

已有局部无限公式仍可作为模块，但扩充固定模板不是主线。未知的是如何跨过
任意宽完整厚块和高目标证明的瓶颈；第一轮的数百倍节省是可用的新起点，
离 3×100 还有尚未解决的规模障碍。
