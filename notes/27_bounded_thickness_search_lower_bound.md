# 27 —— 有限厚块查表无法改变完整 SG 搜索的指数底数

日期：2026-10-14。状态：`[推导]`、`[独立核验]`。全部计算在本机。

本节补上 notes/17 的几何计数与实际搜索之间的一道缺口：指数多个可达图，
本来不代表求解器一定访问它们。本节构造一个对子历史封闭的真实连通族，
证明它们在指定的完整 SG 搜索中全部被访问，而且全部需要展开 mex。

这是对**一类搜索方法**的下界，不是 Node Kayles 本身的复杂度下界，也不是
新空盘胜负公式。它给出比 notes/26 的有限测速更明确的路线判断：继续扩大
固定厚块的整组件查表，无法改变这一搜索的指数底数。任意环境中的局部
改写、真正的接口归约和只求 P/N 的策略搜索不在本定理限制之内。

## 1. 精确的算法范围

考虑从完整 `3×N` 出发的精确、单线程记忆化 SG 展开：

1. 分连通分量，规范上下/左右反射，异或相同分量抵消。
2. 已知值直接查表；路径/环直接求值；安全 180° 对称给出零值。
3. 未命中归约的连通状态枚举全部真实着法，允许按保持图的矩形对称合并。
4. 再允许一个**理想整组件 oracle**：它可以瞬间准确求解任何最长连续完整
   三格列 `7` 不超过 W 的组件，甚至可以覆盖该范围的全部复杂缺损和任意
   多个厚块。W≥2。

实际 notes/26 的完整核心规则只是 W=5 的很弱子集。本节甚至把这个范围内
所有组件都当成已经免费解决，仍证明剩余展开下界。Oracle 必须作用于
整个组件；如果它能改写组件内部的一小块，则不属于上述限制。

求解必须完成，不因内存/时间预算提前退出；主 SG 记忆表从空表开始，
路径表和上述 oracle 可以预先提供。缓存命中本身当然允许，下面证明这些
缓存条目必曾在该次空盘求解中被计算。
这是算法框架的任意宽度结论；当前 C 位掩码仍只支持 42 列。

## 2. 受保护族：一边的不对称标记，加另一边的完整厚块

令

\[
t=N-W-2\ge1.
\]

取任意长度 t 的正则外行历史词 h，要求 `h₁=1`，即首手固定为左上角。
正则条件沿用 notes/17：相邻非零字母同行列距至少 2，异行至少 3。
在 h 后加 W+2 个零，得到长度 N 的真实历史

\[
H=h\,0^{W+2};\qquad M_H=F_N\setminus N[H].
\tag{1}
\]

所有这些历史都是原空盘上的独立集，可按从左到右执行。

**保护引理。** 每个 M_H，以及执行首手之后的每个上述历史前缀，都具有：

- 连通且横跨全部 N 列；
- 第一列恰为 `4`，最后一列为 `7`；
- 最后 W+1 列全部为 `7`；
- 包含度为 4 的顶点；
- 没有非恒等的上下、左右、180° 矩形自对称。

**证明。** notes/17 的全跨连通定理给出第一项。左上角落子删除第一列上、
中格，留下下格；正则间距禁止后续异行子删除它，所以第一列为4。h 的子
最多删除第 t+1 列外格，第 t+2,…,N 列完全不受影响，恰有 W+1 列。
它们包含一个完整 `3×3`，其中中行中列的度为4。

上下反射改变第一列的单个下格；左右反射和180°旋转将一格端列送到三格
端列，都不能保持图。因此不存在三种非恒等矩形对称。N≥W+3≥5，不涉及
`3×3` 转置。删除任意后续历史子使间距增加，仍为正则词，首手和零后缀
仍保留；故上述论证也覆盖每个历史前缀。∎

引理立即排除路径、环、安全旋转以及厚度≤W的整个组件 oracle。图只有
一个组件，所以相同组件抵消无效。矩形着法轨道在这些状态中全部是单点。

## 3. 不仅可达，而且一定进入完整 SG 搜索

空盘本身在 N≥5 时有度4顶点，最长完整列段为 N>W，不是路径或环。
180°对称也不安全：N为奇数时固定中央中格，N为偶数时中央两个中格互为
相邻伙伴。因此空盘需要枚举着法；左上角是它的一个矩形着法轨道代表。

对每个 H，从这个首手开始，按列从左到右执行其非零字母。保护引理说明
每个中间状态都不命中上述任何归约，也没有可省略的矩形着法轨道。
因此每一条历史对应一条必须计算的搜索依赖链。

缓存不会破坏这个结论：若某个中间状态已缓存，它不是由允许的 oracle
返回的；其值此前只能由同一个完整 mex 展开得到，所以其全部后继依赖
此前已被计算。对这条链归纳，最终 M_H 的规范键必已在缓存里，并且
至少一次展开了自己的全部真实着法。

**规范键互异。** notes/17 保证不同 H 的剩余掩码不同。若两个本族掩码有
相同矩形规范键，它们必由上述三种反射之一互相变换。但上下反射把首列4
变为1，另外两种把首列变为7，都不能把本族变回本族。故只能恒等，H相同。
空行/空列修剪也没有作用，因为这些图全跨且含完整三列。

这比“总可达几何有指数多个”更强：这里的指数族不能因现有归约、轨道合并
或别的分支提前缓存而从已计算状态集合中消失。

## 4. 精确下界、固定 W 的紧阶与次线性 W 的指数率

令 b_t 为长度 t、首字母为1的正则词数。用 notes/17 的末两列聚合状态：
u=末两列都零，v=末列有子，w=倒数第二列有子而末列零，得到

\[
(u,v,w)\longmapsto(u+w,\,2u+w,\,v),\qquad
(u_1,v_1,w_1)=(0,1,0).
\]

其特征多项式仍为 `x³−x²−x−1`，所以

\[
\boxed{b_1=1,\ b_2=1,\ b_3=2,\quad
b_t=b_{t-1}+b_{t-2}+b_{t-3}\ (t\ge4).}
\tag{2}
\]

因此 `b_t=Θ(ρ^t)`，`ρ=1.839286755214…`。这来自状态递推，不是样本拟合。
前三项、矩阵及非负不可约矩阵的主特征值也保证主项系数为正。

**搜索下界定理。** 上述算法完成空盘 SG 时，至少计算

\[
\boxed{S_N\ge b_{N-W-2}}
\qquad\text{个不同的连通状态，且枚举着法数}\qquad
\boxed{Q_N\ge N\,b_{N-W-2}.}
\tag{3}
\]

第二式因为每个受保护图每列非空，至少有N个顶点；每个顶点都是当前真实
着法，且它的矩形轨道只有自己，mex展开不能省去这些手。

固定任意有限 W 时，(3) 为 `Ω(ρ^N)` 个状态、`Ω(Nρ^N)` 手。
notes/17 给出的全可达连通几何上界是 `O(ρ^N)` 个；每个缓存状态至多3N
手。因此对该展开框架有紧阶

\[
\boxed{S_N=\Theta(\rho^N),\qquad Q_N=\Theta(N\rho^N).}
\tag{4}
\]

计数指主搜索缓存与其真实着法，不包括 oracle 的内部实现成本。
组件提取、规范化、编号和机器字成本可能增加总时间；不将 (4) 写成精确
运行时间阶。

更强地，允许 W=W(N) 随棋盘增长，只要 W(N)=o(N)，仍有

\[
\lim_{N\to\infty}\frac{\log S_N}{N}=\log\rho.
\tag{5}
\]

下界由 `b_{N-W(N)-2}=ρ^{N-o(N)}`，上界仍由全可达语言给出。
因此即使把所有厚块最长段至多 `sqrt(N)` 的复杂连通组件都免费解决，
这种**整组件查表 + 完整mex**的模式仍保持相同指数率。

### 用图本身的厚块，而不是列掩码来表述

还可以把 oracle 条件改为：**任意连通图，只要每个双连通块的顶点数都
不超过 B，就瞬间返回其 SG**。双连通块是没有内部割点的块，故这是图本身
的性质，不依赖某个三行嵌入或哪个字母被称为7。块之间仍可有任意多割点、
桥及任意长的复杂链。

令

\[
k=\max(3,\lfloor B/3\rfloor+1),\qquad t=N-k-1\ge1.
\]

在首字母为1的任意正则 t 列历史后加 k+1 个零，保护末 k 列完整网格。
完整 `3×k` 是双连通图：外围顶点形成一条环，中行内部顶点分别连向上下
外围；删去任意单点后，剩余外围仍连成路径或环，每个剩余中行内部点仍
接到它。因此这3k个顶点属于整个后继图的同一个双连通块，且3k>B。
该 oracle 在这条历史的所有前缀上均不能使用。

其余不对称、真实依赖和规范键互异的证明完全相同，所以

\[
S_N\ge b_{N-k-1},\qquad Q_N\ge N b_{N-k-1}.
\tag{6}
\]

固定 B 仍得到相同紧阶；B=B(N)=o(N)仍得到 (5) 的相同指数率。
这个版本说明：把全部小厚块及它们的任意复杂连接都查表解决，仍不足以
改变完整展开的指数率。若能对一个大组件**内部**的厚块建立上下文替换，
则可直接跳出本定理的限制；不能把这里的下界套到这种算法上。

这不意味着只要处理线性宽度就一定成功；它只是这一模式摆脱指数率的
必要条件。真正的局部上下文改写、跨割点的游戏接口压缩或策略证明，可以
不逐一计算这些键，完全可能突破本定理的算法范围。

## 5. 独立检查：实际缓存成员，不能拿另行求值冒充访问

`scripts/protected_strip_search.py` 给出历史构造与无需搜索的计数。
`tests/verify_protected_strip_search.py` 用坐标集合枚举合法独立历史，**不使用
正则间距条件**，以实际全跨连通性筛选；检查构造计数、全部反射规范键
互异、保护块、度4顶点及每个历史前缀。

C核验先完成空 `3×N`，再在同一记忆表里查询所有受保护目标。要求后续
查询新增记忆状态和枚举着法都为0，每个目标只增加一次组件缓存调用。
因此这些目标确实在原空盘求解中已经计算，不是探针把它们另行补算出来。
配置0、7、15、23、31全部检查，N=8,10,…,20；源码SHA256写入审计。

独立坐标共检查2,282个最终构造状态、7,070个历史前缀，拒绝3,733个虽为
合法独立集、却不能保持全跨连通的种子。C缓存成员核对总计6,580项，全部
确实已缓存，没有新增状态或枚举手。
双连通保护块另检查宽3–9时全部126个单点删除，剩余图均连通。

```bash
python3 scripts/protected_strip_search.py --width 24 --cutoff 5
# b17=10609 个强制展开状态，至少 254616 手。
make test-protected-strip-search
```

这些核验只检查实现和证明前提的有限实例；任意 N、W 的结论由上面的
历史闭包、缓存依赖与矩阵计数证明。审计为
`data/proofs/protected_strip_search_audit.json`。

本轮没有新的正面厚块归约，也没有求出完整空盘的无限胜负规律。已明确
排除的是此前不断扩充固定厚块整组件模板的主路线：其收益可以是常数或
有限尺寸变化，但在这一搜索框架下不能改变渐近指数底数。
